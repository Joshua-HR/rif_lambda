RIF 길이별 합성 시험

gen_synthetic_dumps는 RIF 길이를 바꿀 수 있는데, run_synthetic_test는 왜 32심볼 세트만 받을까요? 시험을 문제지(덤프)와 정답지(판정 범위)로 나눠 보면 이유와 고칠 양이 함께 보입니다.

문제지
gen_synthetic_dumps가 덤프를 만듭니다. 폴더 하나('Preset','none')는 길이를 고를 수 있지만, 시험 세트('test')는 32심볼로 고정돼 있습니다.
정답지
run_synthetic_test의 판정 94개(2열 49개)에는 기대 범위가 숫자로 박혀 있습니다. 이 숫자는 Python 모델로 32심볼 세트에 맞춰 정했습니다.
64심볼을 넣으면
먼저 c32_m82_j1 폴더를 찾지 못해 오류로 멈춥니다. 경로를 맞춰도 L90처럼 dBm으로 적힌 판정은 약 3 dB 어긋나 CHECK가 납니다.
고칠 양
94개 중 정답이 길이마다 달라지는 판정은 18개(2열 12개)입니다. 코드 수정은 중간 규모이고, 일의 대부분은 새 정답을 모델로 계산하는 것입니다.

1

문제지와 정답지

합성 시험은 두 단계입니다. gen_synthetic_dumps가 정해진 조건(세기, 키, 멀티패스, 개수)으로 덤프를 만들고, run_synthetic_test가 그 덤프를 분석 함수에 넣어 나온 값을 미리 정한 범위와 비교합니다. 분석 함수가 맞게 동작하는지는 이 비교로만 판단합니다.

문제지 쪽: 'N'은 폴더 하나 만들 때만 듣습니다

% gen_synthetic_dumps.m, 'test' 세트의 폴더마다 호출되는 함수
function c = mk(base, power, key, count, seed, ...)
c = base;                     % 여기에 사용자가 준 'N'이 들어 있지만
c.N = 32; c.Power = power; ...  % 바로 32로 덮어씀

그래서 gen_synthetic_dumps('D:/rif_test64', 'N', 64)라고 써도 오류나 경고 없이 32심볼 세트가 만들어집니다. 폴더 이름도 sprintf('c32_m%d_j%d', …)로 15곳에 적혀 있습니다. 이 함정은 길이 지원 여부와 상관없이 고쳐야 합니다.

정답지 쪽: 범위가 숫자로 박혀 있습니다

% run_synthetic_test.m, 4단계 H1 감도
res = chk(res, 'h1: L90 MD rule [dBm]', R1.L90(1, 1), -113, -109.5);
res = chk(res, 'h1: L90 Lambda [dBm]',  R1.L90(1, 2), -113.5, -110);

−113 ~ −109.5 dBm는 32심볼 모델값 −111.3 dBm에 통계적 퍼짐을 더한 범위입니다. 64심볼 덤프의 정답은 −114.2 dBm 근처라서, 분석이 완벽해도 이 범위로는 CHECK입니다.

왜 처음에 32심볼 하나로 만들었나 · 목적이 코드 경로 확인이었습니다. 2열/5열 형식, Λ 계산, 스케일 경고, 형식 혼합 오류, 패킷 판정 논리는 길이와 상관없이 같은 코드를 지나므로 한 길이로 충분하다고 봤습니다. · 기존 세트를 그대로 옮겼습니다. 처음 정답지를 만든 Python 생성기 model/gen_dumps.py가 N = 32 고정이고, 저장소의 synthetic_dumps/도 32심볼입니다. MATLAB 'test' 프리셋은 이 배치를 재현합니다. · 가장 쌉니다. 지연 탭 하나당 누적 샘플이 32심볼 3,968개, 256심볼 32,640개(8.2배)라 생성 시간도 그만큼 늘어납니다. 길이별 감도는 이 시험이 아니라 설계 문서 6.4절과 9.3절의 모델 표에서 따로 다뤘습니다. 실제 길이별 검증에 이 시험을 쓰려면 정답지가 길이마다 있어야 합니다.

길이를 고르면, 그 길이의 세트를 지금의 run_synthetic_test에 넣었을 때 생기는 일을 보여 줍니다. 아래 표의 "예상값"은 모델로 이미 계산해 둔 값(설계 문서 6.4절, 9.3절)이거나, 표시한 곳은 그 값에서 끌어낸 추정입니다.

정답이 길이마다 다른 이유

H1(맞는 키)에서 CIR 피크는 누적한 샘플 수 M = (N − 1) × 128에 비례해 커지고, 잡음은 √M에 비례합니다. 그래서 길이가 두 배면 신호 대 잡음비가 약 3 dB 좋아지고, 같은 Pd를 얻는 세기(L90)가 약 3 dB 낮아집니다.

그런데 잔여 CFO 0.25 ppm이 있으면 누적하는 동안 위상이 한 방향으로 돌아 피크가 덜 쌓입니다. 회전량도 길이에 비례하므로 긴 RIF일수록 손해가 커지고, 256심볼은 오히려 128심볼보다 나빠집니다. 그래서 정답지는 "32심볼 범위를 3 dB씩 옮기기"로 만들 수 없고, 길이마다 계산해야 합니다.

4

94개 판정 지도: 무엇이 길이에 따라 바뀌나

run_synthetic_test의 판정을 하나씩 다섯 갈래로 나눴습니다. 칸 하나가 판정 하나이고, 줄이 시험 단계입니다. 칸을 누르면 이름과 32심볼 범위가 나오고, 오른쪽 분류를 누르면 그 분류만 강조됩니다.

덤프 형식

칸을 누르면 판정의 이름, 32심볼 범위, 길이를 바꿀 때 할 일이 여기에 나옵니다.

고칠 곳과 규모

분석 함수(rif_cir_analyze, h0_pfa_analyze, h1_pd_analyze, rif_packet)는 손대지 않습니다. 32심볼의 정답과 결과는 한 자리도 바뀌지 않게 하는 것이 조건입니다.

대상지금바꾼 뒤규모
gen_synthetic_dumps.m'test'가 N을 무시(mk()에서 32), 폴더 이름 c32 15곳, H1 세기 −106 ~ −116 고정, 이동 폴더 −114N을 따르고, 길이별 H1 세기 범위와 이동 폴더 세기를 표로 둠. 루트에 생성 조건 파일(N, 형식, Ppm, Scale)을 남김20–30줄
run_synthetic_test.m경로 c32 15곳, 범위 숫자 고정폴더·파일 이름에서 N을 판별. 정답이 바뀌는 18개(2열 12개)는 길이별 범위 표에서 읽음. 나머지는 그대로50–80줄
model/gen_dumps.pyN = 32 고정N을 인자로몇 줄
정답 계산32심볼 정답만 있음Python 모델로 64·128·256 세트를 만들어, 바뀌는 판정의 범위를 새로 정하고 "그대로"로 분류한 판정도 값으로 확인계산 약 1.5시간
문서TEST_PLAN, 체크리스트, 설계 문서마지막에, 요청하실 때 반영–

바뀌는 판정 하나의 예

% 지금: 32심볼 숫자가 직접 들어 있음
res = chk(res, 'h1: L90 MD rule [dBm]', R1.L90(1, 1), -113, -109.5);

% 바꾼 뒤: 판별한 길이의 범위를 표에서 꺼냄
g = rg.(sprintf('n%d', N));          % N = 폴더 이름에서 읽은 길이
res = chk(res, 'h1: L90 MD rule [dBm]', R1.L90(1, 1), g.L90md(1), g.L90md(2));

길이별 범위 표의 모양

%                 32               64              128              256
% L90md   [-113 -109.5]    [? ?]           [? ?]            [? ?]
%         모델 -111.34     모델 -114.22    모델 -116.56     모델 -116.19
rg.n32.L90md = [-113 -109.5];        % 지금 값 그대로
rg.n64.L90md = [...];                % 2단계 모델 계산으로 확정

64 이상의 칸은 일부러 비워 두었습니다. 모델 L90에 32심볼과 같은 방식으로 통계적 퍼짐을 더해 정합니다. 세트에 들어가는 H1 세기가 바뀌면 퍼짐도 바뀌므로, 세기 범위를 먼저 정해야 합니다.

수정 순서

정답을 먼저 정하고, MATLAB 코드는 그다음에 고칩니다. 정답을 시험할 코드 자신의 결과로 정하면 "같은 값이 다시 나온다"만 확인하게 됩니다.

  1. 설계 확정. 판정 분류(4장 지도)를 확정하고, 길이별 H1 세기 범위·이동 폴더 세기·개수를 정합니다. Python 미러가 다루지 않는 판정(1–9단계 60개 중 17개)에 바뀌는 판정이 있는지 봅니다. Claude · 코드 수정 없음
  2. Python 생성기에 N. 32로 만든 세트가 기존 synthetic_dumps/와 같은지 비교합니다. Claude
  3. 길이별 정답 계산. 64·128·256 세트를 Python으로 만들고 범위 표를 채웁니다. 2열 판정은 같은 CIR이라 5열 계산으로 함께 정해집니다. Claude · 백그라운드 약 1.5시간
  4. MATLAB 생성기. 'test'가 N을 따르게 하고 생성 조건 파일을 남깁니다. 32 출력은 바이트 단위로 지금과 같아야 합니다. Claude
  5. run_synthetic_test. N 판별과 범위 표 적용. 32의 범위 숫자는 그대로 둡니다. Claude
  6. 32 회귀. 기존 세트로 A-1 94/94, A-2 49/49를 다시 확인합니다. MATLAB 실행
  7. 새 길이. 64 → 128 → 256 순서로, 각각 'Scale', 0.2로 끝까지 돌아가는지 본 뒤 전체 세트로 판정합니다. MATLAB 실행
  8. 마무리. CHECK가 나오면 모델 쪽인지 코드 쪽인지 가리고 범위를 조정합니다. 문서 반영은 그다음, 요청하실 때 합니다. 함께
